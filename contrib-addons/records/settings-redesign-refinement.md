# General settings refinement

General uses the reference settings rows. Theme pack, Theme, and Accent color share the Interface language editor edge. Music visualizer is in Advanced Options. High contrast and Reduce motion for add-on visuals are below Accent color. Both use the standard On/Off switch. The accent row has a Reset to default icon on hover or keyboard focus. Reset uses the selected theme's accent, or the built-in accent when no theme is selected.

High contrast retains the selected base accent. If that color does not meet 4.5:1 contrast against every high-contrast control surface, the host uses the first readable shade toward white or black. The selected swatch still shows the base accent. A refused theme, visualizer, or accessibility change returns the control to the saved state. Theme help stays inside the window and closes with Escape.

The theme token cache now materializes its key as a QString. This is an explicit value boundary. The old-expression sanitizer control also passes with the installed Linux Qt 6.8.3 headers. The installed Windows headers use the same forwarding and value ownership. This change does not establish the cause of the reported Extensions hang.

Validation: the current Theme suite passes 11 normal and 11 focused ASAN/UBSAN cases, with leak and stack-use-after-return checks and no diagnostics. Both builds use QT_USE_QSTRINGBUILDER. The focused sanitizer build instruments ThemeService and its test; its pinned existing host dependencies are normal builds. The old-key-only control passes 3 cases. The six affected QML suites pass 134 cases. Six additional shared-switch consumer suites pass 96 cases. There are no failures or skips.

The focused Appearance checks cover the reference width, narrow width, increased scale, native theme selection, authoritative saved state, accent reset, stable swatch selection in high contrast, forward and reverse Tab, pointer reset, and help bounds. Matched dark, light, high-contrast/focus, and narrow renders use the production Appearance component with injected host backends. They are component evidence, not a Windows application capture. Source pins, commands, logs, and renders are recorded in `/tmp/hakone-general-settings/final-proof.json`.
