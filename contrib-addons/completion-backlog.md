- The session platform is not empty. `test_addon_native_session_player.cpp:157` uses two actual players and reduces a known seek-target offset from 18 seconds to 0. Host control, WSS, local priority and actual app assembly also have focused evidence. That test explicitly does not measure output clocks. The drift/rate/uncertainty experiment in `05-visualizers-and-sessions.md:97` remains a validation item if the v1 coordinated-playback claim includes it. It does not require a real watch-party service.
- `06-delivery-plan.md:42,70,82` requires supported-platform and rendering-backend conformance. Linux component proof does not establish a Windows/macOS app, packaged helper, credential store or quit result. Finish the actual supported-target matrix before those promises. Record startup/footprint and hostile computation behavior as Phase 0 requires.
- `02-packages-and-updates.md:153` defines a signed curated install path as well as direct Git. Current package projections correctly report publisherVerified=false. Direct Git works independently and must stay available. The optional curated path still needs a trust-anchor/catalogue verifier and fixtures before it can be called implemented. This does not require a mandatory catalogue or external publication.
- The complete app freshness pass and targeted Subtitle53/native source/quit checks remain integration gates. A passing component suite cannot replace those checks.

## Explicit later work or deliberate exclusions

These are not missing current-profile implementations:

- Public plain HTTP, LAN/private grants and local discovery add-on authority: `01-architecture.md:115` and `03-providers-and-discovery.md:160` reserve separate future contracts. Do not broaden the current HTTPS profile.
- Inbound sockets and WebRTC media transport: `05-visualizers-and-sessions.md:59` states that they are future contracts.
- A real watch-party service: `06-delivery-plan.md:76` places it after the platform prototype. Frame/sample-perfect output is not promised (`05-visualizers-and-sessions.md:95`).
- Metadata file/sidecar write-back: `03-providers-and-discovery.md:119` defers it. Media-specific settings are future scope (`04-ui-themes-and-configuration.md:184`).
- Wider font/icon customization and arbitrary shader/native DSP profiles are outside the current portable profile. The initial hook release may expose a subset (`04-ui-themes-and-configuration.md:78,138`; `06-delivery-plan.md:72`). Missing hooks must still be negotiated correctly.
- Cross-add-on runtime imports remain excluded in v1 (`02-packages-and-updates.md:128`).

UI state updates and navigation already have registry/result-driven paths. Missing reserved host-call names alone do not prove those behaviors are absent. Storage also has a real transactional JSON namespace. The current get/set/remove profile does not implement the architecture's general blob namespace. Keep that distinction visible when the full storage/schema contract is frozen.

## Progress assessment

The current overall effort estimate is about 80–85 percent complete. This estimate includes work beyond the secure desktop foundation and the requested subtitle-provider example. Identity selection, subscriptions, guest adapters, author schemas and tools, and account setup need more implementation work. The remaining platform and integration checks can also find defects that need code changes. These open requirements limit confidence in the estimate.
